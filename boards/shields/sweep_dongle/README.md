# sweep_dongle

Донгл для Ferris Sweep: `nice!nano v2` + WeAct Studio 1.54″ e-paper
(SSD1681, 200×200) + канал к маку по USB CDC-ACM.

## Зачем

Донгл — **central** сплита. Обе половины стали периферией и приклеены к нему
намертво; переключение между устройствами есть только у донгла.

```
[левая половина]  ──BLE split──┐
                               ├──> [донгл: экран] ──BLE HID──> мак / айпад / ...
[правая половина] ──BLE split──┘
                                      ↑ USB CDC (метрики мака, пока есть кабель)
```

### Почему связку половинок нельзя разорвать

- У периферии нет ни BLE-профилей, ни поведения `&bt` — раскладка на ней
  вообще не исполняется, переключать ей нечего;
- `CONFIG_BT_MAX_PAIRED=1` в `config/cradio.conf`: у половины ровно один бонд,
  и это донгл. Никто другой к ней не привяжется;
- адреса половин донгл хранит отдельно от хостов, в `peripheral_addrs[]` с
  ключами настроек `ble/peripheral_addresses/N`;
- `&bt BT_CLR_ALL` с третьего слоя безопасен: `zmk_ble_clear_all_bonds()`
  обходит только массив `profiles[]` с хостами и до `peripheral_addrs[]` не
  добирается. Проверено по `src/ble.c`.

Обратная сторона: перепривязать половину к другому донглу можно только через
прошивку `settings_reset`. Это цена формулировки «намертво».

### Переключение хостов

Раскладка исполняется на донгле, поэтому биндинги `&bt BT_SEL n` с третьего
слоя переключают BLE-профили **донгла** — то есть третий слой стал пультом
выбора устройства. Дописывать ничего не потребовалось.

## Распиновка

| Сигнал панели | Пин nice!nano | GPIO nRF52840 | Ряд |
|---|---|---|---|
| VCC | `VCC` (3.3 В) | — | правый |
| GND | `GND` | — | правый |
| SCL (SCK) | `D15` | P1.13 | правый |
| SDA (MOSI) | `D14` | P1.11 | правый |
| CS | `D2` | P0.17 | левый |
| D/C | `D3` | P0.20 | левый |
| RES | `D4` | P0.22 | левый |
| BUSY | `D5` | P0.24 | левый |

MISO не подключается — SSD1681 ничего не отдаёт.

Порядок пинов на гребёнке модуля WeAct сверять **по шелкографии**, а не по
позиции: у разных ревизий он отличается.

### Почему не штатный `pro_micro_spi`

Дефолтный `spi1_default` у nice!nano сажает MOSI на **P0.10**, а это NFC-вывод.
`CONFIG_NFCT_PINS_AS_GPIO` в дереве ZMK не включается нигде, поэтому P0.09 (`D10`)
и P0.10 (`D16`) как GPIO недоступны. В оверлее pinctrl переопределён: MOSI
уходит на P1.11, MISO не заявляется.

### Питание

Гребёнка `VCC` у nice!nano v2 запитана через ключ на P0.13 (узел `EXT_POWER`,
`zmk,ext-power-generic`). `CONFIG_ZMK_EXT_POWER` по умолчанию `y`, ключ
включается на старте с задержкой 50 мс — но если внешнее питание когда-нибудь
выключится, дисплей встанет. Глубокий сон на донгле отключён.

## Экран

Рисуется через штатный хук ZMK `zmk_display_status_screen()`
(`CONFIG_ZMK_DISPLAY_STATUS_SCREEN_CUSTOM`), код — в `dongle/src/screen.c`.

Отдельная политика обновления e-paper не понадобилась: `display_tick_cb` в ZMK
— это просто `lv_task_handler()`, а LVGL уходит во flush только по
инвалидации. То есть панель обновляется ровно тогда, когда меняется текст.
Отсюда два требования:

- `CONFIG_LV_Z_VDB_SIZE=100` — полноэкранный буфер (200×200×1 бит = 5000 байт).
  При меньшем LVGL сбрасывает кадр полосами, а `ssd16xx` делает refresh на
  каждый `display_write` — вместо одного обновления вышло бы несколько подряд;
- `set_text_if_changed()` в `screen.c` — `lv_label_set_text` инвалидирует
  область независимо от того, изменился текст или нет.

Весь текст на экране — ASCII: встроенные шрифты Montserrat кириллицы не
содержат.

## Kscan-заглушка

Клавиш нет, но ZMK требует `zmk,kscan`. `zmk,kscan-mock` не подошёл: без
свойства `events` он не компилируется (`DT_N_S_kscan_P_events_LEN`), а задержка
события в нём кодируется 15 битами — отложить дольше 32.7 с нельзя. Поэтому
обычный `zmk,kscan-gpio-direct` на один физически не разведённый вывод `D9`.

## Протокол от агента на маке

Строки в CDC-ACM, ключи в произвольном порядке, незнакомые игнорируются:

```
layout=RU cpu=23 mem=61 disk=142 batt=87 chg=1
```

Раз в 2–5 секунд — чаще e-paper всё равно не перерисуется.

## Этапы

1. **Экран + мак** — сделано в прошивке, ждёт железа и агента.
2. **Агент на macOS** — LaunchAgent, `TISCopyCurrentKeyboardInputSource`,
   `host_statistics64`, `volumeAvailableCapacityForImportantUsage`,
   `IOPSCopyPowerSourcesInfo`.
3. **Подключение к сплиту.** `CONFIG_ZMK_SPLIT=y` + `ZMK_SPLIT_ROLE_CENTRAL=n`
   здесь, `ZMK_SPLIT_BLE_CENTRAL_PERIPHERALS=2` на левой половине. Батареи
   половин приходят даром; активный слой в v0.3 центральный периферии не шлёт
   (в транспорте только `POLL_EVENTS`, `INVOKE_BEHAVIOR`, `SET_PHYSICAL_LAYOUT`,
   `SET_HID_INDICATORS`) — план обойтись `INVOKE_BEHAVIOR`, запасной вариант
   добавить свой тип команды.

## Сборка

```
tools/build.sh sweep_dongle
```

Собирает в контейнере `zmkfirmware/zmk-build-arm:stable`, кладёт результат в
`firmware/`. Подробности и подготовка воркспейса — в шапке скрипта.
